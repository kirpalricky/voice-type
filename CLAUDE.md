# yapboard — Agent Workflow

Default execution hierarchy for bugfix/feature work in this repo — applies by default, not just when explicitly invoked:

- **Sonnet (this session)** — manager. Diagnoses root cause via read-only investigation first (or dispatches `haiku-researcher` for it), coordinates the worktree, dispatches sub-agents, does final build/test verification before merging. Does not write the implementation itself. **Does not re-read files `haiku-researcher` already investigated** — its report (with exact file paths, line numbers, and code excerpts) is the source of truth for that investigation; re-reading the same file yourself after receiving that report is pure duplicate spend. Only re-read if the report is genuinely incomplete or something in it looks wrong — and say so, don't silently double-check by default.
- **`haiku-researcher`** (Haiku) — read-only investigation: "find X", "where is Y", "what does this log say". Reports findings, proposes nothing. Prompts to this agent must ask for exact file paths, line numbers, and verbatim code excerpts — precise enough that the calling Sonnet session never needs to re-open the file itself.
- **`haiku-executor`** (Haiku) — implementation: all actual Write/Edit/Bash code changes, given an already-diagnosed task, in a `.worktrees/` worktree.
- **`opus-consultant`** (Opus) — review and architecture consultation ONLY. Dispatch after `haiku-executor` implements, to review the diff before merge, or for high-stakes design decisions. Read-only — never implements.

When dispatching via the Agent tool, use these `subagent_type` names directly and do **not** pass an explicit `model` override — let each agent's own frontmatter (`model: haiku` / `model: opus`) resolve it. Three `PreToolUse` hooks in `.claude/settings.json` enforce this:

1. Block any Agent call requesting `model: opus` for a `subagent_type` other than `opus-consultant`.
2. Block Sonnet's own `Edit`/`Write` on any `*.swift` file (case-insensitive) outside `.worktrees/` — implementation goes through `haiku-executor` in a worktree, not Sonnet directly.
3. Best-effort block on `Bash` commands that write/rename a `.swift` file outside `.worktrees/` (`>`, `sed -i`, `tee`, `mv`, `cp`, `install`) — **not airtight**: a Python one-liner, `dd`, or base64-decoded write isn't caught.

**One-shot override:** if a trivial direct edit is genuinely warranted (e.g. a one-line fix, or `Package.swift`), tell the user first and let them object, then run `touch .claude/.allow-direct-edit` — the next blocked Edit/Write/Bash call consumes it and proceeds; it does not persist.

**Critical fix #2 (2026-07-31):** after fixing the stdout/stderr bug above, a fresh session still hit blocks — this time on a *legitimate read-only `grep`* command (`grep -rl "waveform\|Waveform" ...`), failing with `HOOK ERROR: could not parse tool_input`. Root cause: Claude Code invokes hook commands via **`sh -c`, not `bash -c`** (confirmed in `hooks.md`) — and on macOS, `/bin/sh` is bash 3.2 running in POSIX-compatibility mode, where the `echo` builtin **silently interprets backslash escapes by default** (unlike normal bash). Every hook piped its JSON payload as `echo "$input" | jq ...` — under `sh`, `echo` mangled the JSON-escaped backslashes in the actual command text (`waveform\\|Waveform` → corrupted) *before* jq ever saw valid JSON, so any Bash/Edit/Agent call whose content contained a backslash (regex, sed pattern, escaped quote, etc.) would fail to parse and fail closed. Fixed by replacing every `echo "$var" | jq` and `echo "$var" | grep` with `printf '%s' "$var" | ...` (printf never interprets escapes). **Lesson for future hook work in this repo: always test hook scripts under `sh -c`, never `bash -c`** — the two shells disagree on `echo` semantics and this bug is invisible under interactive bash testing.

**Critical fix #1 (2026-07-31):** all three hooks originally wrote their block reason to stdout. Claude Code's `PreToolUse` contract *ignores stdout entirely on exit code 2* and reads the reason from **stderr only** — confirmed against `code.claude.com/docs/en/hooks.md` and reproduced directly: a fresh session hit every hook as an opaque `hook error: [command]: No stderr output`, with the actual `BLOCKED:`/`HOOK ERROR:` text never shown to the model at all. Fixed by redirecting every message to `>&2`. **The pre-existing global `rm`-guard hook in `~/.claude/settings.json` has the same bug** (also echoes to stdout) — it has likely never actually shown its "SAFE DELETE" message to any session; not fixed here since it's outside this project, flagged for the user to decide.

**Known limitations, stated plainly (confirmed via Opus review 2026-07-31):**
- The Agent-routing hook only sees *explicit* `model` overrides — it can't block a built-in agent type's (`Explore`/`Plan`/`general-purpose`) implicit inherited-model resolution, which isn't visible in hook input.
- All three hooks fail closed on a `jq`-missing or JSON-parse error (block, not allow) — by design, since these are meant as real guardrails, not just nudges.
- Removing Write/Edit/Bash from `opus-consultant`'s tools genuinely prevents it from *directly* mutating code — Claude Code does not auto-apply a subagent's output as a patch. It does **not** prevent Opus from producing full implementation code in its response text for Sonnet to paste — that's a role-discipline gap these hooks can't close technically.
- Even with all three hooks active, Sonnet will likely still carry a large share of total token cost from orchestration overhead alone (reading reports, maintaining context) — don't expect Haiku to reach 70-80% of total tokens just from this change; re-measure with actual usage.

Sonnet re-verifies `opus-consultant`'s review claims and `haiku-executor`'s "done" claims independently (build/tests, not just the report) before trusting them — but this verification is about *outcomes* (does it build, do tests pass, does the diff match the ask), not re-doing `haiku-researcher`'s *investigation* by re-reading files it already covered. Those are different trust boundaries: verify what changed, don't redundantly re-discover what was already found.
